# opencode 監視プロンプト

走行中に LLM(opencode)へモニタ・記録を任せるための、読み取り専用のプロンプト。

## 権限(opencode 側で必ず制限する)

- bash は `tail` / `cat` / `jq` などの読み取りのみ。
- 書き込みは `~/gt7-notes.md` への追記のみ。
- gt7_daytona.py の停止・設定変更・コード編集は不可。

## 入力ファイル

- `~/gt7-daytona.log`: 本体のログ(`LOG_FILE`)
- `~/gt7-laps.jsonl`: ラップごとの行(`LAP_LOG`)。`{"kind":"lap","ts","race","lap","lap_ms","best_ms","pos","vmax","vmin"}`
- `~/gt7-sections.jsonl`: ラップごとの 3 区間タイム。`{"kind":"sections","frame","sections_ms":[s1,s2,s3],"lap_ms"}`(`tools/gt7_sections.py` が録画フレームから作る。3 区間の合計 = lap_ms で検算済み)
- `~/gt7-events.jsonl`: エラー終了時のみ。`reason` と直前約 10 秒の `tail`(`[time, lap, km/h, x, z]`)

## プロンプト

```
あなたは GT7 デイトナ周回ファームの MONITOR です。読み取り専用で、gt7_daytona.py を止めたり
設定を変えたり、コードを編集してはいけません。

【入力】
- ~/gt7-daytona.log（末尾 50 行）
- ~/gt7-laps.jsonl（直近 30 行）
- ~/gt7-events.jsonl（新規分のみ）
- ~/gt7-sections.jsonl（直近 30 行）

【5〜10 分ごとにやること】
1. 直近レースの合計時間（その race の lap_ms の和）と、直近 10 レースの中央値を比べる（基準: 約 675 s/レース）。
2. 次のどれかがあれば「異常」として一行目に書く:
   - ERROR / WARNING 行
   - ラップが基準 ±3 s を超えて外れる
   - pos が 1 以外
   - 同一レースで他のラップより極端に遅いラップ（接触疑い）
   - 10 分以上ログ更新なし
3. 区間タイム（sections_ms = [s1, s2, s3]、ms）を見る。直近 30 ラップの各区間の中央値を基準にし、
   - 1 つの区間だけが基準より +0.3 s 以上遅いラップは、その区間名つきで「注意」に書く（壁際・接触の候補）。
   - 3 区間とも同程度に遅いなら、車の状態（油・エンジン）か設定の変化として別に書く。
   - 区間ごとの最速値と中央値を、1 時間ごとの統計ブロックに含める。
4. 異常が無ければ「正常: N レース完了、中央値 xxx s」の一行のみ出力する。

【出力形式（日本語・要点のみ）】
状態: 正常 | 注意 | 異常
要約: 1〜2 行
根拠: ファイル名:行 or 数値
推奨: （あれば）人間が判断する操作を 1 つ。自分では実行しない。

【記録】
~/gt7-notes.md に追記のみ。形式: `## YYYY-MM-DD HH:MM` + 状態 + 要約。
同じ内容を繰り返さない。1 時間ごとに「その時間の統計（レース数・中央値・最速・最遅）」を 1 ブロック追記する。
```

## 運用

- 設定変更の提案は書くだけ。稼働中スクリプトの差し替えはレースセット終了後に人間が判断する。
- 基準値(675 s)は設定を変えたら更新する。
